# ManyChat automation creation: captured contract

Source: passive REA capture (`inspect_web_page`, JSON body shapes only) of
`app.manychat.com` while a user created and published an Instagram DM-keyword
automation, 2026-10-16 17:03–17:06 UTC. Evidence ID
`ev_409ed40cbc0bad2007ed9312f6014c4aed76cd1ec6549ddef1ed062b6b510e44`.
83 requests, all HTTP 200, all XHR/fetch to `https://app.manychat.com/{pageId}/…`.
No WebSocket traffic.

REA retains field names and JSON types, never values. Everything below marked
**observed** comes from the capture; **inferred** is our reading of it;
**decision** is a choice made for this project.

## Lifecycle (observed order)

| # | Request | Body (request → response) |
|---|---|---|
| 1 | `POST cms/createFlow` | `{name, path}` → `{flow, fs_object, state}` |
| 2 | `GET flow/getFlowData?ns=…`, `GET cms/getObject?path=/…` | editor load |
| 3 | `POST flow/setDraft` | `{ns, client_id, batch{root_content, contents[]}, coordinates{<oid>{x,y}}}` → `{state}` |
| 4 | `GET keywords/list` | existing rules (for conflict display) |
| 5 | `POST keywords/create?client_id=…` | `{ns, name, channel, type, sort, fetching, keyword_rules[{condition, keywords[]}]}` → `{rule}` |
| 6 | `POST flow/patchDraft` | `{ns, client_id, batch{contents[]}, coordinates}` → `{has_unpublished_changes, state}` |
| 7 | `POST flow/publish` | `{ns, client_id, batch{root_content, context, contents[]}, coordinates}` → `{flow}` with materialized contents |

`analytics/event` (≈55 calls) and `easyBuilder/*` (template-based "quick
automation" path, fired from the dashboard) were left out of scope.

## Shapes

**Flow** (observed): `ns` string (format `content20261016170420_317338`),
`name`, `path`, `status` string, `type` string, `origin` number, `page_id`,
`root_content_id` (null before publish, number after), `draft_batch`,
`has_unpublished_changes`, `has_<channel>_channel` booleans, `ts_created`,
`ts_updated`, and `triggers` with 13 arrays: `keywords`, `welcome_messages`,
`default_replies`, `conversation_starters`, `story_mentions`, `follow_reply`,
`follow_ups`, `intents`, `widgets`, `another_flow`, `cart_replies`,
`external_triggers`, `trigger_rules`.

**Draft content** (observed): `_oid` string, `namespace`, `type`, `caption`,
`content_id` null, `messages[{_oid, type, content{text}, keyboard[]}]`,
`quick_replies{buttons[], settings{timeout, limit_failed,
skip_button_caption, validation_message}}`, `private_reply`, `target`,
`removed` boolean.

**Published content** (observed): numeric `content_id`, `data{_oid,
messages[], message_tag, target}`, `deleted`, stats counters.

**Keyword rule** (observed): `rule_id` number, `channel`, `condition`,
`keyword`, `keywords[]`, `keyword_rules[{condition, keywords[]}]`,
`content_holder`, `namespace`, `sort`, `status`, `is_reserved`, `flow{…}`.

## Inferences

- Draft and published versions are separate; publishing clears the draft.
- `_oid` is generated by the client (canvas coordinates are keyed by it); the
  server assigns numeric `content_id`s on publish.
- The trigger is not a canvas node: it is its own resource linked by `ns`.
- `client_id` identifies the editor session (likely for concurrent-edit
  detection).

## Unknowns

- Values of `status`, `type`, `condition`, `channel` (only "string" seen).
- Button (`keyboard[]`) shape: the arrays were empty in this capture.
- How ManyChat handles keyword collisions between rules.

## Decisions for this project

- Enums: `condition` = `is | contains | starts_with`; `channel` =
  `instagram | facebook | whatsapp | telegram`; flow `status` = `draft | live`.
- Buttons: `{oid, caption, action: "content", targetOid}` or
  `{oid, caption, action: "url", url}` (http/https only), max 3 per message.
- Quick replies, `private_reply`, `client_id` and the other 12 trigger kinds
  are not implemented yet.
- Publish takes the stored draft (no body), and rejects graphs with missing
  root/targets, blank texts or empty contents (HTTP 422).
- The same keyword under the same condition on the same channel is rejected
  (HTTP 409), and keywords are stored lowercased.
